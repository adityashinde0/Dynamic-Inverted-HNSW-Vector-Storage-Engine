1. What Problem Does PS-005 Solve?

Traditional vector databases (e.g. monolithic in-memory HNSW indexes) suffer catastrophic performance degradation under continuous concurrent write and query workloads because inserting vectors mutates node adjacency lists in-place, requiring coarse-grained locks that block search queries.

2. The Architectural Solution: LSM Vector Storage

  • CRC32 WAL: Every vector write is appended to a durable checksummed log before ingestion.
  • Active MemTable: Lock-free in-memory buffer sustaining 119k+ writes/second.
  • Zero-Lock Rotation: MemTable freezes at threshold (5,000 vectors) and swaps pointers atomically. Searches continue concurrently with zero contention.
  • Segment Builder: Background Rayon pool quantizes vectors using SQ8 (3.55x compression, 72% RAM savings) and indexes an immutable HNSW graph.
  • Concurrent Search Fan-Out: Queries search active MemTable and all published disk segments in parallel via mmap, merging candidates via a bounded min-heap.
