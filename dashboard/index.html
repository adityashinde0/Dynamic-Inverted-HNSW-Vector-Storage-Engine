HACKATHON EVALUATION GUIDE

PS-005 Vector Storage Engine — Judge Mode

1. What Problem Does PS-005 Solve?

Traditional vector databases (e.g., standard HNSW implementations) suffer catastrophic performance degradation under concurrent write and query workloads because inserting vectors mutates the graph index in-place, requiring coarse-grained locks that block search queries.

2. The Architectural Solution: LSM Vector Storage

PS-005 applies Log-Structured Merge (LSM) principles to vector indexing:

  • WAL: Every vector write is appended to a durable CRC32 log before ingestion.
  • Active MemTable: Lock-free in-memory buffer accepting 119k+ writes/s.
  • Rotation & Immutability: At threshold (5,000 vectors), MemTable freezes and rotates into an immutable queue. Queries continue concurrently with zero lock contention.
  • Segment Builder: Background thread quantizes vectors using SQ8 (3.55x compression) and builds an immutable HNSW graph.
  • Concurrent Search Fan-Out: Queries search active MemTable and all published disk segments in parallel via Rayon, merging candidates via a bounded min-heap.
